# Coda connector

Write-only deep connector (create + update) layered on the existing Coda proxy catalog entry.

## Auth and base URL

- API key sent as `Authorization: Bearer <token>` (unchanged catalog entry `providers/coda.go`).
- Catalog `BaseURL` is `https://coda.io/apis`; the connector appends `v1`, matching every request
  example in the docs (`https://coda.io/apis/v1/docs`).
- TODO: the OpenAPI spec's `servers[0].url` is now `https://docs.superhuman.com/apis/v1` (Coda is
  rebranding as "Superhuman Docs"), while the prose docs and samples still use
  `https://coda.io/apis/v1`. The catalog base URL was left as is; it needs a human decision.

## Write objects

| Object | Create | Update |
|---|---|---|
| `docs` | `POST /docs` (201, created doc) | `PATCH /docs/{docId}` (200, `{}`) |

- Create body (`DocCreate`): `title`, `folderId`, `timezone`, `sourceDoc` (a doc id to copy),
  `initialPage`. Update body (`DocUpdate`): `title`, `iconName`.
- The doc's name is written as `title` but returned as `name` (read-only in metadata).
- `RecordData` is sent as the JSON body unchanged. On update the response is empty, so
  `RecordId` is the id that was passed in.

Metadata comes from `metadata/schemas.json`, generated by schemagen from `metadata/schemagen.json`.

## Requested but not implemented

- **rows (table rows)**: `POST /docs/{docId}/tables/{tableIdOrName}/rows` and
  `PUT /docs/{docId}/tables/{tableIdOrName}/rows/{rowIdOrName}` need a doc id and a table id in
  the path that the builder chooses (unsupported pattern `dynamic-url-inputs`). Insert is also
  bulk-only (`rows: [...]`, `bulk-operations`). Use the proxy.
- **tables, columns**: Coda has no create or update endpoint for tables or columns. It only lists
  and gets them, under `/docs/{docId}/...`. Cell values are written through rows.
- **delete**: out of scope ("no delete").

## Async writes

Coda queues most mutations and returns 202 with a `requestId`. You can check whether a change has
been applied with `GET /mutationStatus/{requestId}`. Doc create returns 201 and update returns 200.
The connector does not poll. A doc that was just created or renamed may take a few seconds to
appear through the API.

## Rate limits

From https://coda.io/developers/apis/v1#section/Using-the-API/Rate-Limiting: writing data
(POST/PUT/PATCH) is limited to 10 requests per 6 seconds, and listing docs to 4 requests per
6 seconds. The limits apply per user. This repository has no `server/shared/limiter`, so they are
documented here only.
