# Lightfield

Read-only deep connector for the Lightfield CRM REST API (public beta).

## Auth

API key created by a workspace admin (Settings > API keys), sent as `Authorization: Bearer sk_lf_...`.
The key needs `accounts:read`, `contacts:read`, `opportunities:read` and `members:read`.
Docs: https://docs.lightfield.app/using-the-api/api-keys

Every request also carries `Lightfield-Version: 2026-03-01`; the connector adds it to its own requests.
Proxy callers must add it themselves (the catalog has no way to attach a fixed non-auth header).

## Base URL

`https://api.lightfield.app`, with `/v1` added by the connector. The OpenAPI spec declares no `servers`;
the host comes from every example request in the docs.

## Objects

| Object          | Endpoint                | Schema source                                   |
|-----------------|-------------------------|-------------------------------------------------|
| `accounts`      | `GET /v1/accounts`      | catalog + `GET /v1/accounts/definitions`        |
| `contacts`      | `GET /v1/contacts`      | catalog + `GET /v1/contacts/definitions`        |
| `opportunities` | `GET /v1/opportunities` | catalog + `GET /v1/opportunities/definitions`   |
| `members`       | `GET /v1/members`       | catalog only (members have no definitions call) |

`members` are the workspace users (what the customer calls "users"). A member's `$user` relationship holds
its user id. The docs do not say which object type `$owner` points to; to be confirmed against a live
`definitions` response. Relationships to `account`/`contact`/`opportunity` carry `ReferenceTo` in metadata.

The catalog (`internal/metadata/objectsMetadata.json`) is generated by `scripts/openapi/lightfield/metadata`.

## Record shape

Records nest values: `fields.<key> = {value, valueType}` and `relationships.<key> = {cardinality, objectType, values}`.
Read lifts each field to the top level as its `value`, and each relationship as its `values` (list of ids).
System keys keep their `$` prefix (`$name`, `$owner`); custom keys are bare slugs. On a key clash, top-level
properties win over fields, and fields over relationships; metadata follows the same rule. `Raw` is untouched.

## Pagination

`limit`/`offset`, at most 25 records per page. A page shorter than `limit` is the last; the next-page token is
the next offset.

## Incremental read

Lists are sorted by `createdAt` (newest first) and the docs list no filter on `updatedAt` (it is a top-level
property, not a filterable field). `Since`/`Until` are therefore applied by the connector to `updatedAt`
(falling back to `createdAt` when `updatedAt` is null), and every incremental read pages through the full list.
List results come from a search index and may lag recent writes.

## Rate limits

25 requests per second per organization for list calls (Search) and for definitions (Read); 429 with `Retry-After`.
https://docs.lightfield.app/using-the-api/rate-limits
